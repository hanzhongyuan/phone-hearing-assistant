# DSP 实现与验证

本模块是可独立运行的 Java 数字信号处理器。它实现助听实验所需的确定性处理链，不把增益、压缩器或限幅器包装成“AI 模型”。神经网络增强由上层音频引擎调用，输出 PCM 再进入本模块。

## 接口与数据单位

- 包名：`org.example.phonehearingassistant.dsp`。
- `new HearingDsp(DspConfig)` 建立独立状态，配置会深复制。
- 每次 `process(float[256])` 接收 16 kHz 单声道、归一化到 `[-1,1]` 的 PCM，返回 256 个立体声帧，即长度 512、左右交错的数组。
- 返回数组复用，必须在下次调用前消费；也可调用 `process(input, output)` 写入调用方数组。
- `setConfig(config)`、`reset()` 和 `process()` 必须来自同一音频线程；UI 应将快照交给音频线程，不要并发修改处理状态。
- 所有 `dB` 设置均为数字域的 dBFS 或相对增益。没有耳机校准时，不存在可靠的 dB SPL、dB HL 或骨导输出力级换算。
- `getOutputPeakDb()` 只报告应用内部数字峰值；`getFeedbackReductionDb()` 报告频谱抑制器当前最大衰减。

## 处理链

```text
单声道 PCM → 非有限值清理和输入夹取
→ 512 点 FFT / 256 点 hop / sqrt-Hann 分析窗
→ 可选温和 Wiener 谱抑制 → 可选持续窄带峰抑制
→ 模式 1: 保持频率 / 模式 2、3: 每通道频率映射
→ 每通道 8 频带能量检测与 WDRC → 插值增益
→ 逆 FFT / sqrt-Hann 合成窗 / 50% overlap-add
→ 启动淡入 → 快速峰值保护 / 平滑软膝 / 硬上限
→ 左右交错 PCM
```

通道中心频率为 125、250、500、1000、2000、3000、4000、6000 Hz。相邻中心的几何均值划分能量检测频带，增益在 log-frequency 轴上插值。每通道独立拟合和处理，但手机拾音源仍是一个单声道麦克风，并不恢复双耳空间定位。

FFT 的逆变换包含 `1/N`。分析和合成使用同一周期性 sqrt-Hann 窗，平方窗的 50% overlap-add 恰好为 1。清除直流及 Nyquist 点。内部帧移对应 16 ms / 256 samples 的信号延迟；这不是端到端延迟，未包含采集块等待、AI、系统混音、Bluetooth、耳机缓冲。

## 相对听阈拟合

`DspConfig.fitRelativeThresholds(left, right)` 接收每通道八个数字听阈。`NaN` 表示未测；未测点为 0 dB 增益，不能推断成正常听力。实验拟合使用：

`gain[b] = clamp(0.45 × (threshold[b] − best_measured_threshold), 0, 18 dB)`。

这是透明、有限增益的**相对阈值整形启发式**，不是 NAL-NL2、DSL，也不是经过临床验证的处方。统一升高全部数字听阈不会自动提高增益，避免在缺少声学校准的情况下把手机音量或佩戴变化误认为听力损失。

骨传导会跨颅传递；没有临床掩蔽和校准设备，不能把左右输出通道测试解释为独立左右耳蜗的骨导听阈。改变耳机、手机音量、系统音效、佩戴位置、接触压力后应重新测试。舒适上限需由上层流程保守采集和约束，不能通过本模块从阈值反推出真实最大舒适输出。

## 宽动态范围压缩

默认阈值 `−42 dBFS`、比例 `2:1`、能量包络 attack 8 ms / release 120 ms，逐带逐通道计算：

`compressionDb = max(0, inputBandLevelDb − thresholdDb) × (1/ratio − 1)`。

目标增益包含用户增益、各带拟合增益和压缩衰减，以 30 ms 时间常数平滑。检测依据当前频谱能量的标定 RMS，不是麦克风位置的声压。压缩比允许 1–6；关闭压缩仍保留最后的输出限幅。

## 频率映射

模式 2 和模式 3 共用同一映射器。模式 3 的 TTS PCM 需先转换为 16 kHz，再喂入同一处理器；只调整 TTS 的“音调”不会代替这里的带宽映射。

1. **全部频谱压缩**（`mappingType=0`）：`f_out = low + f_in × (high−low) / 8000`。每个正频率输入 bin 都向选定范围内的输出 bin 贡献能量，DC/Nyquist 除外。完整源频谱被压入较窄区间，必然丢失频谱分辨率，多个成分可能碰撞，音色和清晰度可能下降。
2. **保留低频的高频压缩**（`mappingType=1`）：`f≤low` 保持；`f>low` 使用 `low + (f−low) × (high−low)/(8000−low)`。这一选项保留部分自然低频，输出不全部落在 `[low, high]`。

映射根据相邻帧的相位差估计瞬时频率，以 phase-vocoder 式相位累积维持跨帧连续性，输出正频率后重建共轭对称谱。碰撞使单帧能量增加时只衰减、不向上归一化。当前为实验性频率降低器，未对多人说话、瞬态或复杂音乐完成听觉评价；它不声称把所有音色或语音信息无损塞入听者的残余频段。

左右通道可分别配置目标区间，默认 300–3000 Hz，最小宽度 250 Hz。频率目标是用户根据测试选择的可听区间，并不保证该用户实际可听清映射后的语音。

## 噪声和反馈选项

- **Wiener**：因果最小统计噪声估计，频谱增益有 0.18 下限并平滑。它是温和的传统备选算法，不是 GTCRN/DeepFilterNet 等网络，也未声称达到这些模型的语音增强质量。
- **持续窄带抑制**：检测某频点相对周边持续突出的能量，连续约 160 ms 后加深衰减并扩展到邻近 bin，缓慢恢复。它可以削弱啸叫，也可能衰减纯音乐音符或持续元音；它没有参考回授路径建模，**不是 NLMS/PEM 自适应反馈抵消**，不能保证蓝牙延迟下稳定。检测未捕捉到的反馈仍可能存在，实机需要低音量测试、断连停止和紧急停止。

## 输出保护

默认数字峰值上限 `−18 dBFS`，允许范围 `−90` 至 `−6 dBFS`。低于 `−60 dBFS` 的舒适上限也会保持，不会被向上夹取。瞬时峰值触发快速衰减，80 ms 释放；最后 20% 幅度使用连续软膝，并以硬边界兜底。处理器拒绝非 256 样本输入块，NaN/Infinity 输入替换为静音且计数；输出每个样本强制有限。启动前 20 ms 淡入。

数字限幅不能保证实际耳内声压或骨导刺激安全。系统音量和外设放大仍在本模块下游；必须由应用限制路由、处理断连、提示系统音量变化，实际听力安全需要硬件标定和专业评估。

## 自动化证据

Windows 上在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File tests/dsp/run.ps1
```

只依赖 JDK，测试不依赖 Android、Gradle 或网络。测试是已知信号的黑盒性质验证，并非逐行重复实现。当前通过 12 项：

| 验证项 | 本机实测结果 |
| --- | --- |
| FFT 正逆转换 | 最大误差小于 1e-12 |
| 透明 OLA 与延迟 | 相对 RMS 误差约 2.1e-8；延迟 256 samples |
| 左右独立 6 dB 增益 | 6.000 dB |
| 2:1 压缩 | 输入变化 12.04 dB，输出变化 6.08 dB |
| 全带映射 | 6000 Hz → 左 2324.2 Hz / 右 2099.6 Hz，按不同区间设置 |
| 模式 3 PCM 映射 | 与模式 2 相同 |
| 高域压缩 | 125 Hz 保留，6000 Hz → 2298.8 Hz |
| 输出上限与异常值 | 随机过载和 NaN/Inf 输出保持有限且低于 −18 dBFS 上限 |
| 极低舒适上限 | −60、−70、−81、−90 dBFS 均保持；过载输入输出不越限 |
| 持续纯音抑制 | 测试 2000 Hz 纯音约 15.1 dB 衰减 |
| 传统 Wiener 路径 | 测试白噪声能量约降低 0.5 dB，属温和处理 |
| 配置验证 | 缺测不拟合、深复制、异常数值清洗 |
| CPU 粗测 | 桌面 Java 约 0.116 ms / 16 ms hop；不能推定手机功耗和延迟 |

上表模式 2 和模式 3 合并在一个测试函数，因此 runner 汇报 12 项。这些结果没有证明语音可懂度改善，也没有替代 Android 生命周期、蓝牙路由、实际骨导耳机、不同听损人群的测试。应另测各模式的 STOI/ESTOI、SI-SDR、真实端到端延迟、输出电平、语音理解率和主观舒适度。
